# 中文速览

## 本章定位

开篇第一张「全景图」。从单台服务器起步，随着用户量从 0 增长到百万级，系统在不同阶段需要做什么——每个阶段解决什么瓶颈、引入什么组件、有什么代价。

不讲编码技巧，讲的是**一个系统从小到大，在不同阶段要分别考虑什么问题**。每次做系统设计时，可以用这章的演进路线当检查清单，避免一上来就钻细节。

## 核心演进路线（6 个阶段）

| 阶段 | 瓶颈 | 引入组件 | 核心动作 |
|:---:|:----|:---------|:--------|
| **1. 单服务器** | 一切跑在一台机器上 | 域名 + DNS + Web 服务器 + 数据库 | 一个 box 跑通全部 |
| **2. 数据库拆分** | Web 和数据库争抢资源 | 独立数据库服务器（关系型/NoSQL） | Web 层和数据库层分离，各自独立扩展 |
| **3. 负载均衡 + 主从复制** | 单点故障、读压力大 | 负载均衡器 + 主库写/从库读 | 流量分发 + 读写分离 |
| **4. 缓存 + CDN** | 数据库读压力过高、响应慢 | Redis（内存缓存）+ CDN（静态资源） | 减少数据库直接查询，降低延迟 |
| **5. 无状态 Web 层 + 多数据中心** | 会话黏连难以水平扩展、单地域风险 | 共享存储（会话数据）+ geoDNS | Web 层无状态化，流量按地域调度 |
| **6. 消息队列 + 数据库分片** | 耗时操作阻塞、单库容量到顶 | 消息队列（异步解耦）+ 分片键 | 异步化 + 数据水平拆分 |

## 关键选型参考

| 场景 | 推荐 |
|:----|:-----|
| 大多数场景 | 关系型数据库（MySQL / PostgreSQL） |
| 超低延迟、非结构化、大量数据 | NoSQL |
| 读多写少、热点数据 | 缓存（Redis）+ 主从复制 |
| 静态资源、全球分发 | CDN |
| 耗时异步任务 | 消息队列 |
| 单库扛不住 | 数据库分片 |

# 原文笔记

以下为已整理的摘抄笔记，保持原有内容和表述不变。

## 阶段 1：单服务器

所有东西跑在一台机器上：Web 应用 + 数据库 + 缓存。

**关键动作**：域名 → DNS → HTTP 请求 → 返回 HTML/JSON。

## 阶段 2：数据库拆分

把 Web 层和数据库层分离到不同服务器，各自可以独立扩展。

**选型参考**：

| 场景 | 选什么 |
|------|--------|
| 大多数场景 | 关系型（MySQL / PostgreSQL） |
| 超低延迟、非结构化、大量数据 | NoSQL |

## 阶段 3：负载均衡 + 数据库主从复制

**负载均衡**：把流量分发到多台 Web 服务器，解决单点故障。

**数据库主从复制**：
- 主库：写操作
- 从库：读操作（通常多个从库）
- 好处：性能↑、可靠性↑、高可用↑

> 💡 **你工作中的用法**：做新需求时，先问自己"这个读多还是写多？"——读多就考虑加缓存或加从库分担。

## 阶段 4：缓存 + CDN

**缓存**：把频繁访问的数据放内存（如 Redis），减少数据库压力。
- 适合：读多写少的数据
- 注意：设置合适的 TTL（过期时间），避免数据不一致
- 驱逐策略优先用 **LRU**（最近最少使用）

**CDN**：把静态资源（图片、CSS、JS）放到离用户近的节点。
- 工作流：用户请求 → CDN 未命中 → 回源获取 → 缓存并提供
- 注意：控制 TTL，不常用资源不要放 CDN（浪费钱）

## 阶段 5：无状态 Web 层 + 多数据中心

**有状态 vs 无状态**：
- ❌ 有状态：会话粘在特定服务器，扩展困难
- ✅ 无状态：会话数据存到共享存储，任意服务器都能处理请求

**多数据中心**：
- 用户就近接入（geoDNS）
- 一个数据中心挂了，全部流量切到健康的

## 阶段 6：消息队列 + 数据库分片

**消息队列**：把耗时的任务异步化，生产者和消费者解耦。
- 例子：用户上传照片 → 放入队列 → 后台处理 → 完成后通知用户
- 好处：高峰期不堵塞，消费者可以慢慢消化

**数据库分片**：
- 把一张大表拆到多个数据库实例
- 分片键要选好（比如 `user_id % 4`），保证数据均匀分布
- 【⚠️ 坑】名人问题：某个用户（如大 V）数据量爆表 → 单独分片或进一步细化

# 实操清单

每次做设计前扫一遍：

```
[ ] 1. 单机能跑通吗？——先别想复杂的
[ ] 2. 需要分离 Web 和数据库吗？——用户量上来了再拆
[ ] 3. 需要负载均衡吗？——多台服务器就要考虑
[ ] 4. 数据库需要主从复制吗？——读多写少就用
[ ] 5. 缓存用得对吗？——读多写少、热点数据先用
[ ] 6. CDN 有需要吗？——图片/静态资源多就用
[ ] 7. Web 层是无状态的吗？——是的话直接水平扩展
[ ] 8. 需要异步处理吗？——耗时操作用消息队列
[ ] 9. 数据库需要分片吗？——单库扛不住了再看
[ ] 10. 监控和自动化有了吗？——日志、指标、CI/CD
```

# 课后练习

下次你做商品卡需求时，拿这个清单对着看一遍：
- 你现在的系统在哪个阶段？
- 这个需求会推动系统往哪个阶段走？
- 你需要提前关注什么（比如要不要加缓存、要不要异步处理）？

**不用写出来，脑子里过一遍就行**。关键是培养"先看全貌，再下手"的习惯。
