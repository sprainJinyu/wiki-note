# 用户学习画像（并发相关）

> 基于对话中观察的思考习惯、思路特点与学习方式，仅做客观记录。

## 思考习惯

- **极度重视最后 1% 的细节**：明确意识到「看似很小的表达偏差，可能导致思路偏移十万八千里」。会主动承认「方向没错，但细节表达有问题」，并立即修正。
- **自我纠错能力强**：在被指出「重入是区别」的错误后，能快速接受官方口径并用自己的话重新表达正确版本。
- **喜欢先建立背景再追问机制**：先把整体模型讲清楚，再追问「通道如何挂起」「被唤醒后执行流从哪里继续」等细节。
- **倾向用「通道 / 分类」思维理解 Condition**：把 Condition 抽象为锁上的独立通道，用「分类通知」理解精确唤醒，而不是死记 API。
- **对控制流细节敏感**：会反复追问 `await()` 返回后是继续执行还是重新判断、`while` 与 `if` 在被唤醒场景下的真实差异。
- **善于把新概念映射到已有场景**：用生产者-消费者模型来验证多 Condition 的价值。

## 当前学习状态

- C01～C04 已完成，能用自己的话复述「今天只带走这一条」。
- 已明确：重入不是 `synchronized` 与 `ReentrantLock` 的区别，两者都支持。
- 已掌握使用成本差异：内置锁省心自动释放，显式锁需手动管理但功能更丰富。
- 已区分中断（别人通知）与超时（自己控制）。
- 已理解公平锁（严格 FIFO）与非公平锁（允许插队）的核心差异。
- 已打通 Condition 作为「通道」的模型：分类等待 + 精确唤醒；被唤醒后从 `await()` 下一行继续，必须用 `while` 再检查。
- 已收拢选择标准：只有明确需要中断、超时、多 Condition 或公平策略时，才主动选 `ReentrantLock`，否则默认 `synchronized`。
