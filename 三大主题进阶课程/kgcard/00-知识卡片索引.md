# 知识卡片索引

> 整理原则：最小单位 = 元知识点。更大知识点由多个元知识点组合而成。  
> 目的：学会一个就能复用，后续可不断叠加。  
> 卡片之间用 Obsidian 双链互相引用。

> **说明**：本套卡片严格对应你表达过的核心内容，只做润色，不添加。

## 元知识点维护规则（整理卡片前必读）

核心一句：

> **元知识点回答「它是什么 / 它管什么」，不回答「这一步接着干什么」。**

整理前三问，全部「是」才新建元卡：

1. 以后别的主题或组合卡片还会点它的名吗？（复用测试）
2. 不讲完整流程，它自己还说得清吗？（独立性测试）
3. 它是新概念，不是旧概念上的一个动作？（归属测试）

有一句「否」→ 写进已有元卡的「巧思 / 细则」，或写进组合卡片的核心表述，**不新建文件**。

三种落点：

| 落点 | 放什么 |
| :--- | :--- |
| 元知识点 | 可单独命名、可被引用的概念 |
| 组合卡片的核心表述 | 把若干元卡串成「今天带走的那一条」 |
| 元卡末尾的「巧思 / 细则」 | 流程里漂亮但不可复用的一步 |

标题信号：名词 / 机制名更像元卡；「谁做了什么」的动词短语更像步骤。

发现已经建错：不改内容对错，只做 **降级合并**，并从本索引的元卡列表中移除。

已处理的降级：
- 「成功者成为新哨兵」「释放唤醒 head 后继」→ [[元-等待队列哨兵]] 细则；公平性插队点 → [[元-公平锁与非公平锁]]
- 「await 后的 while 检查」→ [[元-Condition通道]] 细则
- 「三级写路径」「可见性两层机制」从元卡改为组合卡片
