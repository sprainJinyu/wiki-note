# 知识卡片-取任务时的锁与两队

**组成元知识点**：  
[[元-工作线程Worker]] · [[元-任务队列workQueue]] · [[元-Condition通道]] · [[元-等待队列哨兵]]

**核心表述**（基于用户口述润色）：

Worker 没有「同步队列身份 / 条件队列身份」这种分类。它只做两件事：拿到任务就执行；拿不到就等。

第一次创建时，当前任务可以直接丢给它跑。  
跑完之后去调任务队列的获取方法。抢锁发生在这条路径上，锁在队列实现里面。

- 队列里已有任务、又没人抢这把锁：直接拿到就跑，不进同步队列，也不进条件队列。
- 锁被占着：进入同步队列，等的是「待执行任务所在队列」那把锁。
- 抢到锁但拿不到任务：调 Condition，进入条件队列挂起。

同步队列里躺的是没抢到这把锁、正在等锁的线程，不是正在执行任务的 Worker。

>标记：`LinkedBlockingQueue` 的 `putLock` / `takeLock` 双锁分离，本次只听到课纲口径，用户尚未用自己的话复述完整，本卡不写进双锁细节。
