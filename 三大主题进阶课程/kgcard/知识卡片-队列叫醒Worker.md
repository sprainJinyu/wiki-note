# 知识卡片-队列叫醒Worker

**组成元知识点**：  
[[元-工作线程Worker]] · [[元-Condition通道]] · [[元-任务队列workQueue]]

**核心表述**（基于用户口述润色）：

满了 core 之后，任务先入队。空闲 Worker 在同一条队列上 `take`，等的条件是「队列里有任务」。  
锁在队列上，不是线程池另开一套派发。

这里有两个队列，都是柜门锁的内部结构，不是 Worker 的两种身份：

- **条件队列**：抢到锁但柜是空的，放锁去挂起。
- **同步队列**：还没抢到任务队列那把锁，在这里等锁。

`notEmpty` 的 `signal`：把条件队列里第一个人挪到同步队列，再唤醒他去获锁。  
`signalAll` 是把所有人都加进同步队列再唤醒，其他场景才用，入队吸醒不走这条。

不是所有等 `take` 的人一起被激活去抢同一个任务；一次只叫醒一个，代价更小。
