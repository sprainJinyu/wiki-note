# 知识卡片-四种饱和拒绝策略

**组成元知识点**：  
[[元-RejectedExecutionHandler]] · [[元-任务队列workQueue]] · [[元-core与max门槛]]

**核心表述**（基于用户口述润色）：

第 4 段触发之后，内置四种策略：

1. `AbortPolicy`（默认）：明确拒绝，抛 `RejectedExecutionException`，交给调用 `execute` / `submit` 的那条线程处理。
2. `DiscardPolicy`：丢掉当前这份提交，不抛异常。
3. `DiscardOldestPolicy`：不丢当前这份，丢掉队列里最早进来的那份，把新的留下来。
4. `CallerRunsPolicy`：调用 `execute` / `submit` 的那条线程自己执行 `task.run()`。调用方被拖慢，提交速率下降，间接形成背压。

可丢的海量日志：用 `DiscardPolicy`，丢掉当前这份。  
不能丢的任务：用 `CallerRunsPolicy`，可以慢，但不把任务扔掉。

>标记：`execute` 与 `submit` 的异常可见性尚未口述。C08 尚未通关。
