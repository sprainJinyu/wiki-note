# 知识卡片-商品详情请求链路

**组成**：[[元-ThreadLocal]] · [[元-CountDownLatch单向倒数]] · [[元-Semaphore许可]] · [[元-ConcurrentHashMap桶]] · [[元-LongAdder]] · [[元-RejectedExecutionHandler]] · [[元-工作线程Worker]]

**场景**（用户口述润色）：Tomcat Worker 接请求 → 写入用户/租户 → 并行查价格/库存/评价 → 拼页。

- 用户/租户：`ThreadLocal`，拦截器 `afterCompletion` 里 `remove()`。
- 三份结果：`CountDownLatch`。查完的线程 `countDown()` 即可离开，不用互等。栅栏会让先到的人直到最慢的那个到齐。
- 库存下游并发上限：`Semaphore(20)`，此刻最多 20 个许可。
- 评价缓存：`computeIfAbsent`，没有才查下游。
- 成功次数：`LongAdder`，避免单点 CAS 把 CPU 打满。
- 业务线程池打满：评价可丢，`DiscardPolicy` 丢当前这份；订单不能丢，`CallerRunsPolicy` 由提交方执行形成背压。

**注**：`CallerRuns` 的提交方若是 Tomcat Worker，背压会机在容器线程上。三路查询要提交到业务池里，Latch 才有独立的工作线程可以 `countDown()`。
