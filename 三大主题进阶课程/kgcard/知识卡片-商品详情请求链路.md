# 知识卡片-商品详情请求链路

**组成**：[[元-ThreadLocal]] · [[元-CountDownLatch单向倒数]] · [[元-Semaphore许可]] · [[元-ConcurrentHashMap桶]] · [[元-LongAdder]] · [[元-RejectedExecutionHandler]] · [[元-工作线程Worker]]

**场景**（用户口述润色）：Tomcat Worker 接请求 → 写入用户/租户 → 并行查价格/库存/评价 → 拼页。

- 用户/租户：`ThreadLocal`，拦截器 `afterCompletion` 里 `remove()`。同一条 Worker 下一单再 `get()` 同一把钥匙，清不掉就串号。
- 三份结果：`CountDownLatch`。查完 `countDown()` 即可离开。
- 库存并发上限：`Semaphore(20)`。
- 评价缓存：`computeIfAbsent`。
- 成功次数：`LongAdder`。
- 业务池打满：评价 `DiscardPolicy`；订单 `CallerRunsPolicy`。

不同等级、能不能丢不一样的任务，不要共用一个 `ThreadPoolExecutor`。共用只有一套队列和拒绝策略，评价会占满 Worker 与 `workQueue`，订单跟着 `offer` 失败。

`CallerRuns` 的提交方若是 Tomcat Worker，背压顶在容器线程上。三路查询要交给业务池，Latch 才有独立线程可以 `countDown()`。
