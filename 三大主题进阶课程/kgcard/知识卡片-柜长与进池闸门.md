# 知识卡片-柜长与进池闸门

**组成元知识点**：  
[[元-任务队列workQueue]] · [[元-阻塞入队与非阻塞入队]] · [[元-core与max门槛]] · [[元-工作线程Worker]]

**核心表述**（基于用户口述润色）：

线程池实例里常驻的是：工作线程、任务队列、计数器、拒绝策略。

一次提交按顺序问：核心线程数够不够 → 队列满没满 → 最大线程数够不够 → 再走配置的拒绝。

`offer` 失败的目的：把「队列满了」交回池子，才能进入第 3 段扩非核心线程；有第 3 段，才有机会把最大线程数打满，打满之后才触发拒绝。

柜长不同，闸门走法不同：

- 容量为 0：没有冗余存放缓冲。核心线程都在跑时，新任务就走扩非核心 Worker；人数也拉满且仍塞不进去，才拒绝。
- 默认长到 `Integer.MAX_VALUE` 的链表阻塞队列：可以不停往里堆任务，实际上很难到上限，可能堆到 OOM；第 3、4 段难以触发。

>标记：四种拒绝策略各自干什么、`execute` 与 `submit` 的异常可见性，用户本次未口述，本卡不写。C08 尚未通关。
