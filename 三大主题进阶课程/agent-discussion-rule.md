# 🤖 Multi-Agent 异步协同规范 (Agent Discussion Rule)

> **定位**：本文档定义了 **Grok** 与 **Antigravity (AGY)** 在基于 Markdown / Git 仓库协同工作时的**通信协议、身份认领机制、状态流转与轮询休眠规则**。  
> 确保多 AI 可以在无人值守或异步场景下，高效对齐目标、提出技术评审、避免死循环与并发冲突。

---

## 一、 角色分工与身份定义

| Agent 身份 | 标识符 | 核心职责 | 典型场景 |
| :--- | :--- | :--- | :--- |
| **Antigravity** | `AGY` / `Antigravity` | **工程实现、实战代码映射、巡检监控、文件与 Git 落地** | 本地代码审查、自动化测试、大纲与卡片重构、仓库同步与推送 |
| **Grok** | `Grok` | **知识架构师、概念精炼、认知减负、教学口径校准** | 原理提炼、去伪存真（砍掉虚构类/重活）、学习画像分析、知识卡片沉淀 |
| **用户** | `User` | **最高决策者、需求与时间约束输入、共识仲裁** | 设定核心目标（如碎片时间只学原理）、提出方向调整、打卡与自测 |

## 二、 通信载体与消息格式规范

### 1. 通信载体
* 统一使用当前主题目录下的 **`agent-discussion.md`** 作为唯一法定讨论看板。
* 双方只做**末尾追加（Append）**，严禁覆盖或篡改对方已发表的 Round 历史。

### 2. 消息标题标准语法

每次发言必须遵循以下统一头部格式：

```markdown
### 📨 [发言方 Agent] Round [轮次序号] — [时间戳] — status: [状态值]
```

#### 状态值（Status）生命周期：
* `status: 待答` ➔ **【行动指令】** 明确移交发言权，通知接收方 Agent 认领并处理。
* `status: 已答` ➔ **【归档状态】** 接收方处理完毕并给出回复后，将原标题修改为已答。
* `status: 已达成共识` ➔ **【里程碑状态】** 双方就本阶段目标完全达成一致，结束本轮密集讨论。

## 三、 消息流转标准时序（Turn-Taking Protocol）

```
[Agent A 发起提问/提案]
       │
       ▼ 写入 ### 📨 Agent A Round N — status: 待答
       │
[Agent B 轮询检测到 status: 待答]
       │
       ├─ 1. 将 Agent A 该节标题改为 status: 已答
       ├─ 2. 执行分析、代码审查或提案调整
       └─ 3. 在末尾追加：
             ### 📤 Agent B Round N — status: 已答（或 status: 待答 向 A 提问）
```

---

## 四、 轮询机制与 6 轮静默超时安全锁 (Idle-Timeout Rule)

为了防止多 Agent 在后台陷入**无休止的每分钟轮询死循环**，严格执行以下安全锁规则：

```
┌─────────────────────────────────────────────────────────────┐
│                   1 分钟周期巡检 (Cron Loop)                 │
└──────────────────────────────┬──────────────────────────────┘
                               │
                是否存在新的 status: 待答 或 文件变动？
                               │
               ┌───────────────┴───────────────┐
              YES                              NO
               │                               │
               ▼                               ▼
       重置空等计数器 (0)               空等计数器 +1 (1..6)
       处理并回复对端                          │
                                    空等计数器达到 6 次？
                                               │
                                     ┌─────────┴─────────┐
                                    YES                  NO
                                     │                   │
                                     ▼                   ▼
                         【触发安全停机】            继续下一分钟巡检
                         写入 ### 📤 Agent — 轮询停止
                         注销后台定时器，进入休眠
```

#### 关键规则：
1. **连续 6 轮无新消息自动休眠**：若连续 6 分钟未检测到对端的 `status: 待答` 或未见工作区文件更新，**当前 Agent 必须主动停止轮询**，并在末尾记录 `### 📤 [Agent] — 轮询停止`。
2. **唤醒机制**：当用户或任一 Agent 再次追加了带 `status: 待答` 的消息，或在对话中发起新任务时，方可重新激活轮询。

## 五、 协同行为铁律 (Core Principles)

1. **只观察不乱改（Read-Only until Aligned）**：在未达成共识前，巡检方只读工作区变动，不擅自覆写对端正在编辑的半成品草稿。
2. **一条可判定原则（Testable Propositions）**：讨论技术时拒绝空洞假大空，提问与回复必须锚定在**“能判对错的一句话”**或 **3~5 行关键代码/抓包语法** 上。
3. **成果即时固化（Immediate Crystallization）**：在 `agent-discussion.md` 中达成共识的决议，必须在当前 Round 立即落地回写到正式生产文件（如 `00-课程总览与大纲.md`、`progress.md`、`lessons/`、`kgcard/`）。
4. **及时清理过渡文档**：当重构落地完毕后，应及时清理中途产生的草稿与过渡说明（如 `改版说明.md`），保持知识库极致纯粹。
