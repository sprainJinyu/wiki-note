# C13 · 上下文透传：线程池复用杀手与阿里 TTL 解法

> **今天只带走这一条**：`InheritableThreadLocal` 只能在 `new Thread()` 创建瞬间拷贝父线程上下文，**在线程池线程复用时完全失效并引发数据串号**；阿里开源的 `TransmittableThreadLocal` (TTL) 依靠对任务进行包装，在**任务提交瞬间抓取快照、在工作线程执行前注入、执行后还原**，完美解决微服务 TraceId 与登录上下文的透传（场景 C）。
> **用时**：15–20 分钟。

---

## 1. 原理

### 一、 三代上下文传递演进

```
1. ThreadLocal             ──> 仅限单线程内部，子线程读不到
2. InheritableThreadLocal  ──> 仅在 new Thread() 初始化时父子拷贝；线程池复用时失效且污染
3. TransmittableThreadLocal ──> 任务提交抓取 ➔ 执行前回放 ➔ 执行后恢复 (线程池复用安全)
```

---

### 二、 TTL 核心生命周期（三步法）

```
[业务主线程]                                          [线程池 Worker 线程]
     │                                                        │
1. 提交任务 ──> Capture (抓取主线程当前 TTL 上下文快照)         │
     │                                                        │
     └────────── 放入阻塞队列排队 ─────────────────────────────> │
                                                              │
                                   2. Replay (回放快照到 Worker 的 ThreadLocal 中，
                                              并备份 Worker 原有值)
                                                              │
                                   3. 执行业务任务 run() ...
                                                              │
                                   4. Restore (恢复 Worker 执行前的原始上下文，防污染)
```

---

### 三、 生产标准接入写法

```java
// 1. 声明上下文容器
public static final TransmittableThreadLocal<UserContext> USER_TTL = new TransmittableThreadLocal<>();

// 2. 包装线程池（推荐修饰 Executor）
Executor ttlExecutor = TtlExecutors.getTtlExecutor(businessThreadPool);

// 3. 正常提交，上下文自动跨线程透明透传
ttlExecutor.execute(() -> {
    UserContext ctx = USER_TTL.get(); // 完美获取主线程透传的上下文！
});
```

---

## 2. 误区

**「微服务链路追踪日志丢 TraceId，只要把底层 `ThreadLocal` 改成 `InheritableThreadLocal` 就能解决。」**  
**致命误解！** 生产几乎 100% 使用线程池。核心线程初始化后长期存活，后续复用执行新任务时根本不会重新触发 `Thread.init()`，导致新请求获取到的是几天前第一次执行该任务残留的陈旧 TraceId。

**「接入了 TTL 框架后，HTTP 拦截器里就不用写 `remove()` 了。」**  
**错误！** TTL 解决的是“任务在线程池执行期间的跨线程抓取与恢复”，但在 Web 主线程请求结束时，仍必须在 `finally` 中主动调用 `USER_TTL.remove()` 清理主线程的 ThreadLocalMap。

---

## 3. 自检

1. **为什么说 `InheritableThreadLocal` 遇上线程池是“灾难组合”？**  
   *提示：不仅新上下文传不进去，还会把之前请求残留的上下文错误读出，造成脏读与严重的用户串号事故。*
2. **阿里 TTL 实现跨线程透传的核心底层依托于什么机制？**  
   *提示：通过装饰器（`TtlRunnable` / `TtlCallable`）在任务提交时 capture 快照，并在执行包裹逻辑中进行 replay 和 restore。*
