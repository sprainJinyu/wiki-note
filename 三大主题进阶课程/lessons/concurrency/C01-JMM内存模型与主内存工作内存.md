# L01 · JMM：没有同步，就不保证可见

> **今天只带走这一条**：没有同步时，线程之间不保证能看见彼此对共享变量的修改。JMM 用「主内存 / 工作内存」描述这件事——工作内存是抽象，不是一根内存条。
> **用时**：15–20 分钟。读完能复述即可，不必写代码。

---

## 1. 原理

Java 用**共享内存**做线程通信：共享变量放在堆里，多个线程读写同一份数据。

问题：CPU 为了快，不会每次都真正访问那份「内存里的值」。寄存器、写缓冲、多级 Cache 都会留副本。所以「我写了」不等于「别的线程现在能读到」。

JMM（Java Memory Model）不管 Cache 线路怎么走，它只给程序员一套规则：**什么时候必须看见**。为了讲这套规则，它画了两层抽象：

```
线程 A  ──  工作内存 A  ──┐
                          ├──  主内存（共享变量）
线程 B  ──  工作内存 B  ──┘
```

* **主内存**：所有线程共享的那份共享变量。
* **工作内存**：每个线程私有的抽象，**涵盖**寄存器、写缓冲、Cache 里的副本。它不是 JVM 里多出来的一块物理区，也不是 L1 的别名。
* **线程不能直接改对方的工作内存**。可见的路径是：A 把写刷新到主内存，B 再从主内存看到新值。没有同步时，JMM **不规定**这两步何时发生。

和「堆 / 栈」不是同一层概念：堆栈是 JVM 运行时怎么切内存；JMM 是规则，回答可见性、有序性、原子性。局部变量在栈上、线程私有，不走这套共享可见性问题。

---

## 2. 误区

**「工作内存 = L1 缓存，volatile = 每次从主内存读。」**

工作内存是模型，一次对应到硬件会同时碰到寄存器、写缓冲、Cache，对不上就不必硬对。`volatile` 的真实保证是下一张卡的事；本节先记住：普通共享变量在没有同步时，**可以一直看见自己的旧副本**。

单线程感觉不到这个问题：有 as-if-serial，重排和延迟都不能让单线程自己的结果变错。

---

## 3. 自检

1. **JMM 的「工作内存」是内存条上的区域吗？**
   *提示：不是。它是对寄存器、写缓冲、Cache 副本的逻辑抽象。*
2. **为什么单线程里几乎感觉不到 JMM，多线程里「改了却没改」？**
   *提示：单线程有 as-if-serial；多线程没有同步时，JMM 不保证工作内存何时和主内存对齐。*
